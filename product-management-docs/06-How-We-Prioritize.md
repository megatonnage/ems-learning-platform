## Prioritization Framework

### RICE Scoring
| Factor | Description | Score |
|--------|-------------|-------|
| **R**each | How many users will this impact? | 1-10 |
| **I**mpact | How much will this help users? | 0.25-3 |
| **C**onfidence | How sure are we about the above? | 0-100% |
| **E**ffort | How much work is this? (person-months) | |

**RICE Score = (Reach × Impact × Confidence) / Effort**

---

## Our Prioritization Rules

1. **P0 (Critical)**
   - Blocks users from core functionality
   - Legal/compliance requirement
   - Safety issue

2. **P1 (High)**
   - Significantly improves user experience
   - Aligns with quarterly goals
   - Clear user demand

3. **P2 (Medium)**
   - Nice to have
   - Incremental improvement
   - Lower user impact

4. **P3 (Low)**
   - Would be cool
   - Low confidence in impact
   - High effort, low reward

## The "Fun vs Helpful" Balance

**Both principles must be considered:**

| Feature | Fun Score | Helpful Score | Priority |
|---------|-----------|---------------|----------|
| Example | High | High | Do first |
| Example | High | Low | Consider |
| Example | Low | High | Consider |
| Example | Low | Low | Don't do |

**Rule:** Features with both high fun AND high helpful get priority.
